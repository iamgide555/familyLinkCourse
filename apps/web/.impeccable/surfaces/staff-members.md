# Staff Members Surface

**Mode:** Operate. **Scope:** extend established staff app with real paper intake, search and profiles; preserve existing mint/teal, Sarabun/Kanit, focus and control sizing.

## Direction Contract

- **Thesis:** staff can find an existing person or save paper intake, then immediately recognize the saved record.
- **Entry:** persistent Thai navigation offers `ค้นหาสมาชิก` and `เพิ่มสมาชิกจากใบสมัคร`; signed-in identity and explicit logout remain available. No inactive course/settings navigation or invented metrics.
- **Search:** visible label, explicit search button, recent records before search, readable row links, member number and phone for disambiguation, clear loading/empty/error state and pagination.
- **Intake:** basic name/contact fields first; only names required for incomplete paper entry. Optional personal, household and contact details grouped with semantic sections. Thai labels remain visible; error summary/inline fields retain values and focus first problem.
- **Duplicate review:** same normalized name plus birth date shows inline matches with explicit existing-record links and a reason before creating a separate person. Shared phone alone never warns or grants access.
- **Profile:** member name and number lead, saved message is announced, statuses are words, edit is obvious. Show authorized intake, explicitly selected caregiver, and emergency contact without hidden gestures.
- **Composition:** established work surface, text and row hierarchy; no dashboard card grid. Single-column at narrow widths; cap horizontal gutters when text grows. Code-led local extension under approved workflow; no new world or comp-led build.
- **Finish:** batch desktop/mobile/user-width screenshots and empty/error/review states; independent scoped finish review and documentation required. Real form/reference labels remain unprovided; do not mark full M1-T2 accepted.
