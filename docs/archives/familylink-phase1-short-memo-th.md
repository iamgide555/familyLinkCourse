# บันทึกสรุปแนวทางโครงการ FamilyLink Phase 1

เรียน ทีม Thai FamilyLink Association

เอกสารฉบับนี้สรุปภาพรวมเบื้องต้นของโครงการระบบลงทะเบียนและจัดการคอร์สสำหรับ FamilyLink ในระยะที่ 1 เพื่อให้ทีมเข้าใจแนวทางระบบ ขอบเขตงานหลัก และคำถามสำคัญที่ต้องยืนยันก่อนเริ่มออกแบบรายละเอียด

## ภาพรวมโครงการ

ปัจจุบันการเปิดคอร์สและรับสมัครผู้เข้าร่วมของ FamilyLink ยังใช้หลายเครื่องมือร่วมกัน เช่น Google Forms, Google Sheets/Excel, LINE และเอกสารกระดาษ ทำให้ข้อมูลผู้เข้าร่วมอาจกระจายอยู่หลายที่ และเมื่อต้องเปิดคอร์สใหม่ ทีมงานอาจต้องสร้างฟอร์มและไฟล์ใหม่ซ้ำทุกครั้ง

Phase 1 เสนอให้พัฒนาเว็บแอปพลิเคชันที่ใช้งานง่ายบนมือถือ เพื่อช่วยจัดการงานหลักเหล่านี้:

- สร้างคอร์สและรอบอบรม
- เปิดลิงก์รับสมัครสำหรับแต่ละรอบ
- ให้ผู้เข้าร่วมลงทะเบียนผ่านมือถือ
- เก็บข้อมูลผู้เข้าร่วมไว้ในระบบกลาง
- ดูรายชื่อผู้สมัครและประวัติการเข้าร่วม
- ส่งออกข้อมูลเป็น Excel
- เก็บหลักฐานการยินยอมด้าน PDPA
- รองรับการเชื่อมต่อกับ LINE Official Account เป็นช่องทางสื่อสาร

แนวทางหลักคือให้ LINE เป็นช่องทางส่งลิงก์และแจ้งเตือน แต่ไม่บังคับให้ผู้สมัครต้องมี LINE เสมอไป ผู้สมัครควรสามารถลงทะเบียนผ่านลิงก์เว็บได้โดยตรง

## เป้าหมายของ Phase 1

เป้าหมายหลักของ Phase 1 คือช่วยลดงานซ้ำของทีมงาน และย้ายข้อมูลสำคัญจากไฟล์กระจัดกระจายมาอยู่ในระบบเดียว

ระบบในระยะนี้ควรเน้นงานพื้นฐานก่อน ได้แก่ การเปิดคอร์ส รับสมัคร ตรวจรายชื่อ ส่งออก Excel และเก็บข้อมูล consent ให้ถูกต้อง ส่วนฟีเจอร์ที่ซับซ้อนกว่า เช่น QR check-in, certificate อัตโนมัติ, reminder ผ่าน LINE และ import ข้อมูลเก่าจาก Google Sheets สามารถทำต่อหลังจาก flow หลักใช้งานได้ดีแล้ว

## ขอบเขตงานหลักที่เสนอ

Phase 1 ควรรวม:

- ระบบเข้าสู่ระบบสำหรับทีมงาน
- การสร้างคอร์ส รอบอบรม และวันอบรม
- ฟอร์มลงทะเบียนที่ใช้งานดีบนมือถือ
- ลิงก์ลงทะเบียนสำหรับส่งผ่าน LINE หรือช่องทางอื่น
- ฐานข้อมูลผู้เข้าร่วม
- ประวัติการสมัครของผู้เข้าร่วมแต่ละคน
- หน้าจอรายชื่อผู้สมัครสำหรับทีมงาน
- การ export ข้อมูลเป็น Excel
- การเก็บ PDPA consent
- โครงสร้างระบบที่แยกข้อมูลองค์กร เพื่อรองรับอนาคตหากมี NGO อื่นใช้งาน

## คำถามสำคัญที่ต้องยืนยันกับ FamilyLink

เพื่อให้ระบบตรงกับวิธีทำงานจริง ขอให้ FamilyLink ช่วยยืนยันประเด็นต่อไปนี้

1. ข้อมูลผู้สมัครที่จำเป็นต้องเก็บมีอะไรบ้าง  
   เช่น ชื่อ เบอร์โทร อีเมล อายุ/ปีเกิด จังหวัด ความสัมพันธ์กับผู้ดูแล หรือข้อมูลอื่น คำตอบนี้สำคัญเพราะจะกำหนด field หลักของฟอร์ม และมีผลต่อการค้นหาผู้เข้าร่วมซ้ำในระบบ

2. FamilyLink จำเป็นต้องเก็บข้อมูลอ่อนไหวหรือไม่  
   เช่น ข้อมูลสุขภาพ การวินิจฉัย ความพิการ สภาพครอบครัว หรือปัญหาทางการเงิน หากต้องเก็บข้อมูลเหล่านี้ ระบบต้องมี consent ที่ชัดเจน สิทธิ์การเข้าถึงที่เข้มขึ้น และแนวทางเก็บรักษาข้อมูลที่รอบคอบกว่าเดิม

3. รูปแบบคอร์สเป็นอย่างไร  
   ต้องยืนยันว่าคอร์สหนึ่งมีวันเดียวหรือหลายวัน มีหลาย batch หรือไม่ ผู้สมัครสมัครทั้งคอร์สหรือเลือกบาง session ได้หรือไม่ เพราะข้อมูลนี้จะกำหนดโครงสร้าง course, course run และ session

4. ขั้นตอนการรับสมัครต้องมีการอนุมัติหรือไม่  
   ต้องยืนยันว่าผู้สมัครที่กรอกฟอร์มแล้วถือว่าสำเร็จทันที หรือทีมงานต้อง approve ก่อน รวมถึงต้องมีระบบ waitlist และจำกัดจำนวนที่นั่งหรือไม่

5. ต้องมีระบบเช็คชื่อและ certificate ใน MVP หรือไม่  
   หากต้องออก certificate ต้องรู้ว่าต้องเข้าอบรมกี่วันถึงจะได้ certificate และข้อมูลอะไรต้องแสดงบน certificate หากยังไม่จำเป็นในระยะแรก สามารถเลื่อนไปหลังจากระบบลงทะเบียนหลักเสถียรแล้ว

6. Excel export ต้องออกมาในรูปแบบใด  
   ขอทราบ column ที่ทีมใช้อยู่ปัจจุบัน และรายงานที่ต้องส่งให้ผู้บริหาร ผู้สนับสนุน หรือหน่วยงานอื่น เพราะ export เป็นจุดสำคัญที่จะช่วยให้ทีมเปลี่ยนจาก workflow เดิมมาใช้ระบบใหม่ได้ง่ายขึ้น

7. LINE Official Account ต้องทำงานแบบใด  
   ต้องยืนยันว่า LINE ควรมีปุ่มลงทะเบียนปุ่มเดียว หรือแสดงรายการคอร์สที่เปิดรับสมัคร และหลังลงทะเบียนแล้วต้องส่งข้อความยืนยันหรือ reminder ผ่าน LINE หรือไม่

8. PDPA consent ต้องใช้ข้อความและกติกาใด  
   FamilyLink ควรยืนยันข้อความ consent วัตถุประสงค์การใช้ข้อมูล ระยะเวลาการเก็บข้อมูล และกรณีที่ต้องลบหรือส่งออกข้อมูลตามคำขอของเจ้าของข้อมูล

## ความเสี่ยงหลักที่ควรระวัง

1. Scope ใหญ่เกินไปใน Phase 1  
   หากทำ registration, LINE automation, QR check-in, certificate, custom form, report และ import ข้อมูลเก่าพร้อมกันทั้งหมด ระยะเวลาและความซับซ้อนจะเพิ่มขึ้นมาก แนะนำให้เริ่มจาก flow หลักก่อน คือ เปิดคอร์ส รับสมัคร ดูรายชื่อ และ export Excel

2. ความเสี่ยงด้าน PDPA  
   หากระบบเก็บข้อมูลสุขภาพ ครอบครัว หรือข้อมูลส่วนบุคคลละเอียดมากขึ้น ความเสี่ยงด้านกฎหมายและความไว้วางใจจะสูงขึ้น ต้องกำหนดให้ชัดเจนว่าเก็บข้อมูลอะไร เพื่อวัตถุประสงค์ใด ใครดูได้ และเก็บไว้นานแค่ไหน

3. ทีมงานอาจยังคุ้นกับ Google Forms และ Excel  
   หากระบบใหม่ใช้งานยากหรือไม่สามารถ export ข้อมูลในรูปแบบที่ทีมต้องใช้จริง ทีมอาจกลับไปใช้วิธีเดิม ดังนั้นหน้าจอ admin ควรเรียบง่าย และ Excel export ควรทำให้ดีตั้งแต่ช่วงแรก

4. พึ่งพา LINE มากเกินไป  
   หาก LINE integration มีข้อจำกัดหรือทำได้ช้ากว่าที่คาด ระบบลงทะเบียนไม่ควรถูกหยุดไว้เพราะ LINE ดังนั้น registration link ควรใช้งานได้ผ่าน browser โดยตรง และทีมงานควรส่งลิงก์เองได้

5. โครงสร้าง multi-tenant อาจซับซ้อนเกินจำเป็น  
   ระบบควรเตรียม `organization_id` เพื่อแยกข้อมูล FamilyLink จากองค์กรอื่นในอนาคต แต่ยังไม่ควรทำ billing หรือระบบสมัครใช้งานสาธารณะใน Phase 1 เพราะจะเพิ่มงานที่ยังไม่จำเป็น

## ขั้นตอนถัดไปที่เสนอ

1. FamilyLink ยืนยันคำถามสำคัญด้านข้อมูลผู้สมัคร คอร์ส รายงาน LINE และ PDPA
2. สรุปขอบเขต MVP ให้ชัดเจน
3. ออกแบบหน้าจอหลักและโครงสร้างข้อมูล
4. เริ่มพัฒนา flow หลัก: สร้างคอร์ส -> ส่งลิงก์ -> ลงทะเบียน -> ดูรายชื่อ -> export Excel
5. ทดลองใช้งานกับคอร์สจริงหนึ่งรอบ แล้วปรับตาม feedback ของทีมงาน

เป้าหมายของ Phase 1 ไม่ใช่การทำระบบใหญ่ทั้งหมดในครั้งเดียว แต่คือการสร้างฐานระบบที่ใช้งานได้จริง ลดงานซ้ำของทีม และพร้อมต่อยอดเป็นระบบที่ครบขึ้นในระยะถัดไป
