# คำถาม FamilyLink Phase 1

วัตถุประสงค์: ยืนยันว่า Phase 1 ควรเก็บข้อมูลอะไรบ้าง ก่อนออกแบบโครงสร้างฐานข้อมูลและฟอร์มลงทะเบียนให้เสร็จสมบูรณ์

## สมมติฐานของโครงการ

- Phase 1 เริ่มต้นกับ Thai FamilyLink Association
- เจ้าของระบบตอนนี้คือ Gide
- ในอนาคตอาจต่อยอดเป็น SaaS เพื่อรองรับ NGO พาร์ทเนอร์อื่น
- ทีมงานใช้ web admin dashboard
- ผู้เข้าร่วมลงทะเบียนผ่านฟอร์มเว็บที่ใช้งานได้ดีบนมือถือ
- ลิงก์ลงทะเบียนส่งผ่าน LINE Official Account หรือทีมงานส่งเองได้
- LINE เป็นช่องทางสื่อสาร ไม่ใช่ตัวยืนยันตัวตนที่บังคับ
- ฐานข้อมูลต้องรองรับการแยกข้อมูลแบบ multi-tenant ตามองค์กร
- ต้องมีการเก็บ PDPA consent ตั้งแต่เริ่มต้น
- หัวหน้า FamilyLink เป็นผู้ตัดสินใจ/อนุมัติคำตอบสุดท้าย แม้จะมีทีมงานหลายคนเข้าร่วมประชุมหารือ
- ภาษาของระบบ: ภาษาไทยเป็นหลัก รองรับภาษาอังกฤษด้วย แต่เน้นทำภาษาไทยก่อน

## คำถามสำคัญที่สุดที่ต้องยืนยันก่อน

1. ฟอร์มลงทะเบียนทุกครั้งต้องมีข้อมูลผู้สมัครฟิลด์ใดบ้าง?
2. FamilyLink จำเป็นต้องเก็บข้อมูลสุขภาพหรือข้อมูลครอบครัวที่อ่อนไหวหรือไม่?
3. โครงสร้างคอร์สเป็นอย่างไร: วันเดียว, หลายวัน, มีหลาย batch, มี session?
4. การลงทะเบียนต้องมีการอนุมัติ, waitlist, หรือจำกัดจำนวนที่นั่งหรือไม่?
5. กติกาการเข้าร่วมแบบใดถึงจะออก certificate ได้?
6. ทีมงานต้องการรายงานหรือ Excel export แบบใดบ้าง?
7. ข้อความ consent PDPA และกติกาการเก็บรักษาข้อมูลต้องเป็นแบบใด?

## ข้อมูลผู้เข้าร่วม

ถามว่าฟิลด์ใดต้องเก็บสำหรับผู้เข้าร่วมทุกคน:

- ชื่อ-นามสกุล
- เบอร์โทรศัพท์
- อีเมล
- บัญชี LINE / การเชื่อมโยงผู้ใช้ LINE
- อายุหรือปีเกิด
- เพศ
- จังหวัด
- อำเภอ
- อาชีพ
- ความสัมพันธ์กับผู้ดูแล (caregiver)

คำถาม:

1. ฟิลด์ผู้เข้าร่วมใดที่จำเป็นต้องกรอก (required)?
2. ฟิลด์ผู้เข้าร่วมใดที่ไม่บังคับ (optional)?
3. FamilyLink ต้องการข้อมูลผู้ติดต่อฉุกเฉินหรือไม่?
4. ถ้าต้องการ ต้องมีฟิลด์ผู้ติดต่อฉุกเฉินอะไรบ้าง?
   - ชื่อ
   - เบอร์โทรศัพท์
   - ความสัมพันธ์
5. ผู้เข้าร่วมควรแก้ไขข้อมูลโปรไฟล์ของตัวเองได้ในภายหลังหรือไม่?
6. หรือให้เฉพาะทีมงานเท่านั้นที่แก้ไขข้อมูลผู้เข้าร่วมได้?

## ข้อมูลอ่อนไหว (Sensitive Data)

ถามตรงๆ ว่าจำเป็นต้องเก็บข้อมูลอ่อนไหวหรือไม่ เพราะจะเพิ่มความเสี่ยงด้าน PDPA

ตัวอย่างข้อมูลอ่อนไหว:

- การวินิจฉัยโรค
- ประเภทความพิการ
- ยาที่ใช้
- สภาวะสุขภาพ
- สภาพครอบครัว
- ข้อมูลผู้ป่วยหรือผู้ที่ได้รับการดูแล
- ข้อมูลความยากลำบากทางการเงิน

คำถาม:

1. ปัจจุบัน FamilyLink เก็บข้อมูลที่เกี่ยวกับสุขภาพอยู่หรือไม่?
2. FamilyLink จำเป็นต้องใช้ข้อมูลนี้ใน Phase 1 หรือไม่?
3. ใครมีสิทธิ์ดูข้อมูลอ่อนไหวนี้ได้บ้าง?
4. ควรเก็บข้อมูลอ่อนไหวไว้นานแค่ไหน?
5. Phase 1 สามารถเลี่ยงการเก็บข้อมูลอ่อนไหวไปก่อนได้หรือไม่?

ข้อเสนอแนะ:

- หลีกเลี่ยงการเก็บเลขบัตรประชาชนและข้อมูลการรักษาพยาบาลโดยละเอียด เว้นแต่จำเป็นจริงๆ
- ใช้เบอร์โทรศัพท์เป็นหลักในการตรวจสอบข้อมูลซ้ำ
- ใช้ LINE user ID เป็นตัวยืนยันตัวตนสำรอง ถ้ามี

## การจัดการผู้เข้าร่วมที่ซ้ำกัน

ปัญหาปัจจุบัน: ผู้เข้าร่วมคนเดียวกันอาจปรากฏในหลาย Google Sheets หรือไฟล์ของผู้จัดงานคนละคน

คำถาม:

1. ปัจจุบันทีมงานตรวจสอบผู้เข้าร่วมที่ซ้ำกันอย่างไร?
2. การตรวจสอบข้อมูลซ้ำควรใช้เบอร์โทรศัพท์หรือไม่?
3. การตรวจสอบข้อมูลซ้ำควรใช้บัญชี LINE หรือไม่?
4. เคยต้องรวม (merge) ข้อมูลที่ซ้ำกันด้วยมือหรือไม่?
5. ควรแชร์ข้อมูลผู้เข้าร่วมข้าม NGO พาร์ทเนอร์ในอนาคตหรือไม่?

ข้อเสนอแนะ:

- ตรวจสอบข้อมูลซ้ำภายในองค์กรเดียวกันด้วยเบอร์โทรศัพท์ก่อน
- เชื่อมโยง LINE user ID เมื่อมีข้อมูล
- ไม่รวมข้อมูลผู้เข้าร่วมข้าม NGO พาร์ทเนอร์ เว้นแต่มีระบบขอความยินยอมในอนาคต

## ข้อมูลคอร์ส

ถามว่าฟิลด์ใดที่ใช้กำหนดคอร์สหนึ่งคอร์ส

ตัวอย่างฟิลด์ของคอร์ส:

- ชื่อคอร์ส
- คำอธิบายคอร์ส
- หมวดหมู่คอร์ส
- ผู้จัดงาน
- สถานที่
- ลิงก์ประชุมออนไลน์
- จำนวนที่รับ (capacity)
- วันที่เริ่ม
- วันที่สิ้นสุด
- วิทยากร
- กลุ่มเป้าหมาย
- คุณสมบัติการรับ certificate

คำถาม:

1. ทีมงานต้องใช้ข้อมูลอะไรบ้างในการสร้างคอร์ส?
2. คอร์สมีการเปิดซ้ำเป็น batch หรือไม่?
3. ควรใช้ template คอร์สเดิมซ้ำสำหรับหลาย batch หรือไม่?
4. คอร์สแต่ละคอร์สเป็นของผู้จัดงานเดียว หรือหลายผู้จัดงาน?
5. คอร์สต้องมีคำอธิบายสาธารณะสำหรับผู้เข้าร่วมหรือไม่?

## รอบอบรมและ Session

ข้อกำหนดที่ทราบแล้ว: บางคอร์สมี 1 วันอบรม บางคอร์สมี 3 วันอบรม

โครงสร้างที่แนะนำ:

- Course = template ที่ใช้ซ้ำได้
- Course run = รอบ/batch ที่เปิดรับสมัครแต่ละครั้ง
- Course session = วันอบรมหรือ session จริงภายใน course run

คำถาม:

1. ผู้เข้าร่วมลงทะเบียนทั้ง course run หรือไม่?
2. หรือผู้เข้าร่วมสามารถเลือก session เฉพาะได้?
3. ข้อมูลใดที่จำเป็นต่อ session?
   - วันที่
   - เวลาเริ่ม
   - เวลาสิ้นสุด
   - สถานที่
   - ลิงก์ประชุมออนไลน์
   - บังคับหรือไม่บังคับ
4. สถานที่ของ session สามารถเปลี่ยนระหว่างวันได้หรือไม่?
5. course run สามารถถูกยกเลิกหรือเลื่อนได้หรือไม่?

## ฟอร์มลงทะเบียน

แนวทางปัจจุบัน: ฟอร์มพื้นฐาน (base form) บวกฟิลด์ที่กำหนดเองได้ (custom fields)

ฟิลด์พื้นฐานควรคงที่ เพื่อให้การรายงาน การตรวจสอบข้อมูลซ้ำ และฐานข้อมูลศิษย์เก่าทำงานได้อย่างน่าเชื่อถือ

คำถาม:

1. ฟิลด์ใดที่ต้องอยู่ในฟอร์มลงทะเบียนทุกครั้ง?
2. ฟิลด์ใดที่อาจเปลี่ยนไปตามแต่ละคอร์ส?
3. ทีมงานควรสร้างฟิลด์กำหนดเองได้หรือไม่?
4. ต้องการฟิลด์กำหนดเองประเภทใดบ้าง?
   - ข้อความสั้น
   - ข้อความยาว
   - Dropdown
   - ตัวเลือกแบบ Radio
   - กลุ่ม Checkbox
   - วันที่
   - อัปโหลดไฟล์
5. ฟิลด์กำหนดเองควรตั้งค่า required/optional ได้หรือไม่?
6. ทีมงานควรสามารถจัดลำดับฟิลด์ใหม่ได้หรือไม่?
7. จำเป็นต้องมี conditional logic หรือรอไปก่อนได้?

ข้อเสนอแนะสำหรับ MVP:

- รองรับฟิลด์ required/optional
- รองรับข้อความ, dropdown, radio, และ checkbox ก่อน
- เลื่อน conditional logic และการอัปโหลดไฟล์ไปก่อน เว้นแต่จำเป็นชัดเจน

## กระบวนการลงทะเบียน

คำถาม:

1. ใครก็ตามที่มีลิงก์สามารถลงทะเบียนได้เลยหรือไม่?
2. ทีมงานต้อง approve ก่อนยืนยันที่นั่งหรือไม่?
3. ระบบต้องรองรับ waitlist หรือไม่?
4. ระบบต้องบล็อกการลงทะเบียนเมื่อคอร์สเต็มหรือไม่?
5. ทีมงานควรสามารถเพิ่มผู้เข้าร่วมแบบ walk-in ด้วยมือได้หรือไม่?
6. ผู้เข้าร่วมควรได้รับข้อความยืนยันหลังลงทะเบียนหรือไม่?
7. ผู้เข้าร่วมควรได้รับการแจ้งเตือนก่อนวันอบรมหรือไม่?

สถานะที่เป็นไปได้:

- Draft (ร่าง)
- Submitted (ส่งแล้ว)
- Approved (อนุมัติแล้ว)
- Waitlisted (รอคิว)
- Cancelled (ยกเลิก)
- Attended (เข้าร่วมแล้ว)
- Completed (เสร็จสิ้น)

## รูปแบบการทำงานของ LINE Official Account

แนวทางปัจจุบัน:

- ผู้เข้าร่วมเพิ่มเพื่อน LINE Official Account
- ผู้เข้าร่วมกดเลือก "ลงทะเบียน"
- LINE ส่งลิงก์ลงทะเบียน
- ทีมงานสามารถส่งลิงก์เดียวกันเองได้ด้วย

คำถาม:

1. เมนู LINE ควรมีปุ่มลงทะเบียนปุ่มเดียว หรือแสดงรายการคอร์สที่เปิดรับสมัคร?
2. ลิงก์ลงทะเบียนควรเจาะจงต่อคอร์ส หรือเป็นลิงก์รายการคอร์สทั่วไป?
3. ผู้เข้าร่วมต้องเพิ่มเพื่อน LINE Official Account ก่อนลงทะเบียนหรือไม่?
4. คนที่ไม่มี LINE สามารถลงทะเบียนได้หรือไม่?
5. การแจ้งเตือนควรส่งผ่าน LINE เท่านั้นหรือไม่?
6. ถ้าผู้เข้าร่วมลงทะเบียนโดยไม่มี LINE การแจ้งเตือนควรใช้ SMS หรืออีเมล?
7. FamilyLink มี LINE Official Account อยู่แล้วหรือไม่?
8. ใครเป็นผู้ดูแล LINE Official Account อยู่ตอนนี้?

ข้อเสนอแนะ:

- ไม่บังคับให้ต้องมี LINE ในการลงทะเบียน
- ใช้ลิงก์ลงทะเบียนเว็บที่แชร์ได้
- ใช้ LINE เป็นช่องทางหลักในการส่งข้อมูล/แจ้งเตือนเมื่อมีให้ใช้งาน

## การเข้าร่วม (Attendance)

คำถาม:

1. ปัจจุบันทีมงานตรวจสอบการเข้าร่วมอย่างไร?
2. ต้องติดตามการเข้าร่วมเป็นรายวัน/รายเซสชันหรือไม่?
3. ใครเป็นผู้เช็คอินผู้เข้าร่วม?
   - ทีมงานสแกน QR code ของผู้เข้าร่วม
   - ผู้เข้าร่วมสแกน QR code ของสถานที่
   - ทีมงานทำเครื่องหมายเข้าร่วมด้วยมือ
4. จำเป็นต้องมี QR check-in สำหรับ MVP หรือไม่?
5. ควรอนุญาตให้แก้ไขข้อมูลการเข้าร่วมด้วยมือหรือไม่?
6. ควรมีการ export ข้อมูลการเข้าร่วมหรือไม่?

ข้อเสนอแนะ:

- เก็บข้อมูลการเข้าร่วมต่อผู้เข้าร่วมต่อ session
- รองรับการบันทึกด้วยมือก่อน
- เพิ่ม QR check-in หลังจากระบบลงทะเบียนใช้งานได้แล้ว

## Certificate

คำถาม:

1. ปัจจุบัน FamilyLink ออก certificate อยู่หรือไม่?
2. certificate จำเป็นต้องมีใน Phase 1 MVP หรือไม่?
3. กติกาการเข้าร่วมแบบใดที่ทำให้ได้รับ certificate?
   - เข้าร่วมครบทุก session
   - เข้าร่วมอย่างน้อย X sessions
   - ทีมงานอนุมัติด้วยมือ
4. ข้อมูลใดต้องปรากฏบน certificate?
   - ชื่อผู้เข้าร่วม
   - ชื่อคอร์ส
   - วันที่ของคอร์ส
   - เลขที่ certificate
   - ลายเซ็น
   - โลโก้องค์กร
5. ผู้เข้าร่วมควรดาวน์โหลด certificate จากลิงก์ได้หรือไม่?
6. ทีมงานควร export certificate เป็นชุดได้หรือไม่?

## PDPA

คำถาม:

1. ปัจจุบัน FamilyLink ใช้ข้อความ consent PDPA แบบใด?
2. FamilyLink มีข้อความที่ผ่านการตรวจสอบทางกฎหมายแล้วหรือไม่?
3. ควรแยก consent ตามวัตถุประสงค์หรือไม่?
   - การลงทะเบียนคอร์ส
   - ข่าวสาร/การติดต่อในอนาคต
   - การใช้ภาพถ่าย/วิดีโอ
   - การแชร์ข้อมูลกับพาร์ทเนอร์/ผู้สนับสนุน
4. ควรเก็บข้อมูลผู้เข้าร่วมไว้นานแค่ไหน?
5. ผู้เข้าร่วมสามารถขอลบข้อมูลได้หรือไม่?
6. ผู้เข้าร่วมสามารถขอส่งออกข้อมูลของตัวเองได้หรือไม่?
7. ใครเป็นผู้รับผิดชอบคำขอลบ/ส่งออกข้อมูล?
8. ควรมีการบันทึก log การเข้าถึงข้อมูลของทีมงานหรือไม่?

ข้อเสนอแนะ:

- เก็บเวอร์ชันของ consent, เวลาที่ยอมรับ, IP/user agent ที่ยอมรับ (ถ้าเหมาะสม) และวัตถุประสงค์
- เก็บประวัติ consent ไว้แม้ข้อความจะเปลี่ยนในภายหลัง

## บทบาทของทีมงานและผู้ดูแลระบบ

คำถาม:

1. ใครสามารถสร้างคอร์สได้?
2. ใครสามารถแก้ไขฟอร์มลงทะเบียนได้?
3. ใครสามารถดูข้อมูลส่วนบุคคลของผู้เข้าร่วมได้?
4. ใครสามารถ export Excel ได้?
5. ใครสามารถลบข้อมูลผู้เข้าร่วมได้?
6. FamilyLink ต้องการหลายบทบาท (role) สำหรับทีมงานหรือไม่?

บทบาทที่เป็นไปได้:

- Platform owner (เจ้าของแพลตฟอร์ม)
- Organization admin (ผู้ดูแลองค์กร)
- Staff (ทีมงาน)
- Viewer (ผู้ดูข้อมูลอย่างเดียว)

## รายงานและการ Export

คำถาม:

1. FamilyLink ส่งรายงานอะไรให้ผู้สนับสนุนหรือคณะกรรมการบ้าง?
2. ปัจจุบันใช้ column อะไรบ้างใน Excel?
3. ต้องการรายงานรายเดือนหรือไม่?
4. ต้องการรายงานรายปีหรือไม่?
5. ต้องการจำนวนผู้เข้าร่วมแยกตามจังหวัดหรือไม่?
6. ต้องการอัตราการเข้าร่วมหรือไม่?
7. ต้องการอัตราการไม่มาหรือไม่ (no-show rate)?
8. ต้องการจำนวนผู้เรียนจบคอร์สหรือไม่?
9. ต้องการจำนวน certificate ที่ออกหรือไม่?
10. การ export ควรตรงกับรูปแบบ Google Sheet ปัจจุบันหรือไม่?

ข้อเสนอแนะ:

- สร้างระบบ Excel export ตั้งแต่ช่วงแรก
- ให้ตรงกับ workflow ปัจจุบันของทีมงานให้มากที่สุด

## การนำเข้าข้อมูลเดิม

คำถาม:

1. ต้องการนำเข้าข้อมูล Google Sheets เดิมเข้าสู่ระบบใหม่หรือไม่?
2. ปัจจุบันมีไฟล์ทั้งหมดกี่ไฟล์?
3. column ในแต่ละไฟล์เหมือนกันหรือไม่?
4. มีข้อมูลซ้ำระหว่างไฟล์หรือไม่?
5. ข้อมูลเดิมสะอาดพอที่จะนำเข้าได้หรือไม่?
6. ควรนำเข้าข้อมูลเดิมก่อนเปิดใช้งานจริง หรือทำทีหลัง?

ข้อเสนอแนะ:

- เริ่ม Phase 1 ด้วยการลงทะเบียนคอร์สใหม่ก่อน
- นำเข้าข้อมูลเก่าหลังจากโครงสร้างฟิลด์ได้รับการยืนยันแล้ว

## เงื่อนไขทางธุรกิจ

คำถาม:

1. คอร์สฟรี, เก็บค่าใช้จ่าย, หรือมีผู้สนับสนุนออกให้? มีค่าธรรมเนียม, เงินมัดจำ, หรือค่าใช้จ่ายบางส่วนที่ผู้เข้าร่วมต้องจ่ายหรือไม่?
2. ปัจจุบันมีคอร์สกี่คอร์สต่อเดือน? แต่ละคอร์สมีผู้เข้าร่วมกี่คน? รวมผู้เข้าร่วมทั้งปีเท่าไหร่?
3. มีกำหนดเวลาหรือเหตุการณ์ที่ Phase 1 ต้องเปิดใช้งานให้ทันหรือไม่ (เช่น รอบอบรมถัดไป, การนำเสนอต่อคณะกรรมการ, รายงานผู้สนับสนุน)?
4. FamilyLink จะใช้ test case/คอร์สจริงใดในการประเมิน Phase 1? ผลลัพธ์แบบใดจาก test case นั้นถือว่าสำเร็จ?
5. ถ้า course run ถูกยกเลิกหรือเลื่อน ผู้เข้าร่วมที่ลงทะเบียนแล้วควรได้รับแจ้งเตือนอัตโนมัติหรือไม่? ย้ายไปรอบถัดไปอัตโนมัติ หรือให้ทีมงานจัดการเอง?

## ขอบเขต MVP ที่เสนอ

สร้างก่อน:

1. องค์กรและระบบเข้าสู่ระบบของทีมงาน
2. การจัดการคอร์สและ course run
3. การจัดการวันที่ session
4. ฟอร์มลงทะเบียนเริ่มต้น (default)
5. ลิงก์ลงทะเบียนที่แชร์ได้
6. โปรไฟล์ผู้เข้าร่วมพร้อม registration snapshot
7. หน้าจอ dashboard การลงทะเบียน
8. การ export Excel
9. ฟิลด์กำหนดเองพื้นฐาน (custom fields)
10. การเก็บ PDPA consent

สร้างถัดไป:

1. การเชื่อมต่อ LINE Official Account
2. การแจ้งเตือนการลงทะเบียน
3. การเช็คชื่อด้วยมือ
4. QR check-in
5. การสร้าง certificate
6. การนำเข้าข้อมูล Google Sheet เดิม
